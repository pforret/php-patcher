# Add upgrade-ubuntu.sh to script an in-place Ubuntu LTS upgrade of a Forge server over SSH

## Request

> add feature
> create new script upgrade-ubuntu.sh
>
> that automates all the steps to upgrade a Forge serve via ssh
> using the steps you just constructed and also inspired by the following script that worked perfectly before:

"The steps you just constructed" = the runbook for a 20.04 Forge server from the session of 2026-10-22, which follows
`docs/faq/ubuntu20.md` option B, plus the pre-flight findings (see Analysis).

The reference script follows. It was pasted with broken encoding (`â€”` for `—`, `âœ…` for `✅`,
etc.) and with `\!` for `!`; both are fixed below. The `.env` example host name was replaced by a
generic `myhost` (public repo: no real server names). Otherwise it is as pasted.

```bash
#!/usr/bin/env bash
#
# upgrade-ubuntu.sh — the repo-side half of an in-place Ubuntu LTS upgrade on a
# Forge / DigitalOcean VPS (20.04 → 22.04 by default). Wraps everything around
# `do-release-upgrade` that can be scripted; the upgrade itself and the reboots
# are deliberately left to a human in a `screen` session.
#
# Runbook: https://github.com/pforret/php-patcher/blob/main/docs/faq/ubuntu20.md
# Wiki:    docs/concepts/ubuntu-inplace-upgrade.md
#
# Usage:
#   bin/upgrade-ubuntu.sh [flags] preflight  <ssh-host>   # read-only: READY / BLOCKED report
#   bin/upgrade-ubuntu.sh [flags] disk       <ssh-host>   # sudo (read-only): where the disk went — biggest dirs, binlogs, logs, caches, old kernels
#   bin/upgrade-ubuntu.sh [flags] nginx-down <ssh-host>   # sudo: stop + mask nginx (sites offline, survives reboots)
#   bin/upgrade-ubuntu.sh [flags] prepare    <ssh-host>   # sudo: backups, mirror swap, port 1022, full-upgrade, Prompt=lts
#   bin/upgrade-ubuntu.sh [flags] postflight <ssh-host>   # sudo: re-add ondrej/php, reinstall PHP, disable sites, restart php-fpm
#   bin/upgrade-ubuntu.sh [flags] nginx-up   <ssh-host>   # sudo: unmask + enable + start nginx (after PHP is verified patched)
#   bin/upgrade-ubuntu.sh [flags] verify     <ssh-host>   # read-only: OS, kernel, PHP versions vs fixed, sites over HTTPS, leftovers
#   bin/upgrade-ubuntu.sh [flags] cleanup    <ssh-host>   # sudo: close port 1022, remove *.distUpgrade / *.save, list backups to delete
#
# Flags (before the verb):
#   --target=<codename>     release the box must end on (default: jammy)
#   --drop-php=<v,v>        PHP versions NOT to reinstall after the upgrade (e.g. --drop-php=7.4)
#   --disable=<site,site>   nginx sites to disable in postflight: sites-enabled symlink,
#                           forge crontab lines and supervisor programs that reference /home/forge/<site>/
#   --fixed=<v:ver,v:ver>   override the per-branch fixed PHP versions used by `verify`
#                           (default: PHP2Shell — 8.2:8.2.35,8.3:8.3.36,8.4:8.4.27,8.5:8.5.12,8.1:8.1.34-9,7.4:7.4.33-31)
#
# The sequence for one server (each verb prints the next step):
#   nginx-down → preflight → [DO snapshot + off-box DB dump] → prepare → reboot
#   → `ssh -t <host> sudo screen -S upgrade do-release-upgrade` → reboot
#   → postflight → `php-patcher host <host>` → nginx-up → verify → cleanup
#
# This script NEVER runs do-release-upgrade and NEVER reboots. Reboots happen
# from the Forge dashboard or with `ssh <host> sudo reboot`.
#
# Sudo password resolution (same as bin/fix_copyfail.sh):
#   1. <HOST_UPPER>_SUDO_PASSWORD line in <repo>/.env  (e.g. MYHOST_SUDO_PASSWORD=...)
#      → fed to `sudo -S` over stdin so the run is non-interactive.
#   2. If not set, falls back to interactive `sudo` over a TTY.
#
# Site list for `verify`: from `bin/forge_mgt.sh sites <host>` when FORGE_API_TOKEN
# resolves, otherwise from /etc/nginx/sites-enabled on the box.

set -euo pipefail

SCRIPT_DIR=$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)
REPO_ROOT=$(dirname "$SCRIPT_DIR")
ENV_FILE="$REPO_ROOT/.env"

TARGET_CODENAME="jammy"
DROP_PHP=""
DISABLE_SITES=""
FIXED_PHP="8.2:8.2.35,8.3:8.3.36,8.4:8.4.27,8.5:8.5.12,8.1:8.1.34-9,7.4:7.4.33-31"
MIN_ROOT_FREE_MB=5120
MIN_BOOT_FREE_MB=300
FALLBACK_SSH_PORT=1022
BACKUP_DIR="/var/backups/ubuntu-upgrade"

die() { printf 'error: %s\n' "$*" >&2; exit 1; }

usage() {
  cat >&2 <<'EOF'
usage: upgrade-ubuntu.sh [flags] preflight  <ssh-host>
       upgrade-ubuntu.sh [flags] disk       <ssh-host>
       upgrade-ubuntu.sh [flags] nginx-down <ssh-host>
       upgrade-ubuntu.sh [flags] prepare    <ssh-host>
       upgrade-ubuntu.sh [flags] postflight <ssh-host>
       upgrade-ubuntu.sh [flags] nginx-up   <ssh-host>
       upgrade-ubuntu.sh [flags] verify     <ssh-host>
       upgrade-ubuntu.sh [flags] cleanup    <ssh-host>

  preflight   — read-only report; verdict READY / BLOCKED with the fix for each blocker
  disk        — read-only (via sudo) space report: top dirs, MySQL binlogs, rotated logs,
                Laravel logs, composer/npm caches, old kernels — with the command that frees each
  nginx-down  — stop + mask nginx so no reboot or upgrade step can serve unpatched PHP
  prepare     — backups to /var/backups/ubuntu-upgrade, DO mirror → archive.ubuntu.com,
                ufw allow 1022, Prompt=lts, apt full-upgrade, autoremove; then YOU reboot
  postflight  — (after do-release-upgrade + reboot) re-add ppa:ondrej/php, reinstall the
                saved PHP package list minus --drop-php, full-upgrade, disable --disable
                sites, restart php*-fpm + supervisorctl restart all; nginx stays down
  nginx-up    — unmask + enable --now nginx, nginx -t
  verify      — OS, kernel, each PHP binary vs the fixed version, php-fpm units, mysql,
                nginx state, every site's HTTPS status, leftover mitigations
  cleanup     — ufw delete allow 1022/tcp, remove /etc/**/*.distUpgrade and *.save,
                list what is left in /var/backups/ubuntu-upgrade

flags: --target=jammy  --drop-php=7.4  --disable=site1,site2  --fixed=8.3:8.3.36,...

The upgrade itself is interactive and is NOT run by this script:
  ssh -t <host> sudo screen -S upgrade do-release-upgrade     (reconnect: sudo screen -x)
EOF
  exit 64
}

# Resolve sudo password for <ssh-host> from <repo>/.env.
# "myhost" → looks up MYHOST_SUDO_PASSWORD. Strips matching surrounding quotes.
load_sudo_password() {
  local host=$1
  local var pw
  var=$(printf '%s' "$host" | tr '[:lower:]' '[:upper:]' | sed 's/[^A-Z0-9]/_/g')_SUDO_PASSWORD
  [[ -f "$ENV_FILE" ]] || { printf '' ; return 0; }
  pw=$(grep -E "^${var}=" "$ENV_FILE" | tail -n1 | cut -d= -f2-)
  pw=${pw%\"}; pw=${pw#\"}
  pw=${pw%\'}; pw=${pw#\'}
  printf '%s' "$pw"
}

# Run a (multi-line) script as root on the remote. Password from .env if available,
# otherwise interactive sudo over a TTY. Output goes straight to the caller.
run_remote_sudo() {
  local host=$1 cmd=$2 pw
  pw=$(load_sudo_password "$host")
  if [[ -n "$pw" ]]; then
    printf '→ using sudo password from %s for %s (non-interactive)\n' "$ENV_FILE" "$host" >&2
    printf '%s\n' "$pw" | ssh -o BatchMode=yes -o ConnectTimeout=10 -T "$host" \
      "sudo -S -p '' env LC_ALL=C.UTF-8 bash -c $(printf '%q' "$cmd")"
  else
    printf '→ no <HOST>_SUDO_PASSWORD in %s — using interactive sudo (TTY)\n' "$ENV_FILE" >&2
    ssh -t -o ConnectTimeout=10 "$host" "sudo env LC_ALL=C.UTF-8 bash -c $(printf '%q' "$cmd")"
  fi
}

# Run a read-only script on the remote as the ssh user (no sudo, no TTY).
run_remote_ro() {
  local host=$1 cmd=$2
  ssh -o BatchMode=yes -o ConnectTimeout=10 -T "$host" "LC_ALL=C.UTF-8 bash -c $(printf '%q' "$cmd")"
}

# Site names for <host>: Forge API when the token resolves, else nginx sites-enabled.
site_list() {
  local host=$1 out
  if out=$("$SCRIPT_DIR/forge_mgt.sh" sites "$host" 2>/dev/null) && grep -q '^| [0-9]' <<<"$out"; then
    awk -F'|' '/^\| [0-9]+ \|/ {gsub(/ /,"",$3); gsub(/ /,"",$12); if ($3 != "default" && $12 == "yes") print $3}' <<<"$out"
  else
    printf '→ Forge API unavailable, using /etc/nginx/sites-enabled on %s\n' "$host" >&2
    run_remote_ro "$host" 'ls /etc/nginx/sites-enabled 2>/dev/null | grep -v "^default$"'
  fi
}

# ---------------------------------------------------------------------------
# preflight — read-only
# ---------------------------------------------------------------------------
cmd_preflight() {
  local host=$1
  ssh -o BatchMode=yes -o ConnectTimeout=10 -T "$host" bash -s "$host" "$TARGET_CODENAME" "$MIN_ROOT_FREE_MB" "$MIN_BOOT_FREE_MB" <<'REMOTE'
HOST=$1; TARGET=$2; MIN_ROOT=$3; MIN_BOOT=$4
blockers=(); warnings=()
st() { local o; o=$(systemctl "$1" "$2" 2>/dev/null) || true; printf '%s' "${o:-$3}"; }

codename=$(lsb_release -cs 2>/dev/null || echo unknown)
desc=$(lsb_release -ds 2>/dev/null || echo unknown)
kernel=$(uname -r)
booted=$(uptime -s 2>/dev/null || echo n/a)

nginx_enabled=$(st is-enabled nginx missing)
nginx_active=$(st is-active nginx inactive)
[[ "$nginx_enabled" == "masked" && "$nginx_active" != "active" ]] \
  || blockers+=("nginx is $nginx_enabled/$nginx_active — run: bin/upgrade-ubuntu.sh nginx-down $HOST")

prompt=$(grep -E '^Prompt=' /etc/update-manager/release-upgrades 2>/dev/null | cut -d= -f2)
[[ "$prompt" == "lts" ]] || warnings+=("Prompt=${prompt:-unset} in /etc/update-manager/release-upgrades (prepare sets lts)")

if grep -qs 'mirrors.digitalocean.com' /etc/apt/sources.list; then
  mirror="mirrors.digitalocean.com (prepare swaps it to archive.ubuntu.com)"
  warnings+=("apt mirror is mirrors.digitalocean.com — do-release-upgrade aborts on it; prepare fixes this")
else
  mirror=$(grep -E '^deb ' /etc/apt/sources.list 2>/dev/null | head -1 | awk '{print $2}')
fi
third_party=$(ls /etc/apt/sources.list.d/ 2>/dev/null | tr '\n' ' ')

root_free=$(df -Pm / | awk 'NR==2{print $4}')
boot_free=$(df -Pm /boot 2>/dev/null | awk 'NR==2{print $4}')
[[ -z "$boot_free" ]] && boot_free=$root_free
(( root_free >= MIN_ROOT )) || blockers+=("only ${root_free} MB free on / (need ${MIN_ROOT}) — apt-get autoremove --purge; apt-get clean; journalctl --vacuum-size=200M; prune logs")
(( boot_free >= MIN_BOOT )) || blockers+=("only ${boot_free} MB free on /boot (need ${MIN_BOOT}) — remove old kernels")
root_pct=$(df -P / | awk 'NR==2{print $5}')

php_bins=$(for b in /usr/bin/php[0-9].[0-9]; do [[ -x $b ]] && printf '%s=%s ' "${b##*/php}" "$($b -r 'echo PHP_VERSION;' 2>/dev/null)"; done)
php_pkgs=$(dpkg --get-selections 2>/dev/null | grep -cE '^php')

mysql_pkg=$(dpkg -l 2>/dev/null | awk '/^ii +mysql-(community-)?server[ -]/ {print $2" "$3}' | head -1)
[[ -z "$mysql_pkg" ]] && mysql_pkg="none installed"
case "$mysql_pkg" in
  mysql-community-server*) warnings+=("MySQL is Oracle's mysql-community-server — after the upgrade run: dpkg-reconfigure mysql-apt-config (select $TARGET) and upgrade mysql-community-*") ;;
esac
mysql_cnf_err=$(mysqld --validate-config 2>&1 | grep -m1 'ERROR' || true)
[[ -n "$mysql_cnf_err" ]] && warnings+=("MySQL option files are invalid — '${mysql_cnf_err#*] }' — mysqld silently SKIPS the rest of that file (bind-address, datadir…); fix only after the upgrade, and never by just moving the line (see runbook)")

ed25519=$(grep -c 'ssh-ed25519' ~/.ssh/authorized_keys 2>/dev/null || true); ed25519=${ed25519:-0}
(( ed25519 > 0 )) || warnings+=("no ssh-ed25519 key in ~/.ssh/authorized_keys — OpenSSH on $TARGET refuses SHA-1 (ssh-rsa) signatures; modern clients negotiate rsa-sha2 so RSA keys usually still work, but add an ed25519 key and keep the DO console open")

command -v screen >/dev/null || warnings+=("screen not installed (prepare installs it)")
command -v do-release-upgrade >/dev/null || warnings+=("update-manager-core not installed (prepare installs it)")
[[ -f /var/run/reboot-required ]] && warnings+=("/var/run/reboot-required is set — reboot before do-release-upgrade")

pro=$(pro status 2>/dev/null | grep -iE 'attached|subscription' | head -1 | sed 's/^ *//')
[[ -z "$pro" ]] && pro="n/a"

ufw=$(sudo -n ufw status 2>/dev/null | head -1 || echo "needs sudo")
[[ -z "$ufw" ]] && ufw="needs sudo"

sites=$(ls /etc/nginx/sites-enabled 2>/dev/null | grep -vc '^default$')
cron_lines=$(crontab -l 2>/dev/null | grep -vc '^#' || true); cron_lines=${cron_lines:-0}

if [[ "$codename" == "$TARGET" ]]; then
  blockers+=("already on $desc — nothing to upgrade; go to postflight/verify")
fi

printf '## %s — upgrade preflight (target: %s)\n\n' "$HOST" "$TARGET"
printf -- '- **OS:** %s (%s), kernel %s, booted %s\n' "$desc" "$codename" "$kernel" "$booted"
printf -- '- **nginx:** %s / %s\n' "$nginx_enabled" "$nginx_active"
printf -- '- **Disk:** / %s MB free (%s used), /boot %s MB free\n' "$root_free" "$root_pct" "$boot_free"
printf -- '- **apt mirror:** %s\n' "$mirror"
printf -- '- **3rd-party sources:** %s\n' "${third_party:-none}"
printf -- '- **Prompt=:** %s\n' "${prompt:-unset}"
printf -- '- **PHP binaries:** %s(%s php* packages selected)\n' "$php_bins" "$php_pkgs"
printf -- '- **MySQL package:** %s\n' "$mysql_pkg"
printf -- '- **Ubuntu Pro:** %s\n' "$pro"
printf -- '- **ufw:** %s\n' "$ufw"
printf -- '- **ed25519 keys in authorized_keys:** %s\n' "$ed25519"
printf -- '- **nginx sites enabled:** %s · **forge crontab lines:** %s\n' "$sites" "$cron_lines"
printf '\n'
if (( ${#warnings[@]} )); then
  printf '### Warnings\n\n'; for w in "${warnings[@]}"; do printf -- '- ⚠ %s\n' "$w"; done; printf '\n'
fi
if (( ${#blockers[@]} )); then
  printf '### Status: ❌ BLOCKED\n\n'; for b in "${blockers[@]}"; do printf -- '- ❌ %s\n' "$b"; done; printf '\n'
  exit 1
fi
printf '### Status: ✅ READY\n\nNext: DigitalOcean snapshot + off-box DB dump, then `bin/upgrade-ubuntu.sh prepare %s`\n\n' "$HOST"
REMOTE
}

# disk — read-only via sudo (du across other users' dirs needs root)
# ---------------------------------------------------------------------------
cmd_disk() {
  local host=$1
  local remote_cmd
  remote_cmd=$(cat <<'EOF'
echo "## disk report"; echo
df -h / /boot 2>/dev/null; echo
echo "### biggest directories (depth 2)"
du -xh --max-depth=2 / 2>/dev/null | sort -rh | head -20; echo
echo "### MySQL binary logs   → free: mysql -e 'PURGE BINARY LOGS BEFORE NOW() - INTERVAL 1 DAY;'"
du -ch /var/lib/mysql/binlog.* /var/lib/mysql/mysql-bin.* 2>/dev/null | tail -1 || echo "none"
echo "### rotated / compressed logs   → free: find /var/log -regex '.*\.\(gz\|[0-9]\)' -delete"
find /var/log -regex '.*\.\(gz\|[0-9]\)' -printf '%s\n' 2>/dev/null | awk '{s+=$1} END {printf "%.1f MB in %d files\n", s/1048576, NR}'
echo "### systemd journal   → free: journalctl --vacuum-size=100M"
journalctl --disk-usage 2>/dev/null | sed 's/^/   /'
echo "### apt cache   → free: apt-get clean"
du -sh /var/cache/apt 2>/dev/null
echo "### Laravel logs per site   → free: find /home/forge/*/storage/logs -name 'laravel-*.log' -mtime +7 -delete"
du -sh /home/forge/*/storage/logs 2>/dev/null | sort -rh | head -8
echo "### storage/app per site (uploads — do NOT delete blindly)"
du -sh /home/forge/*/storage/app 2>/dev/null | sort -rh | head -8
echo "### composer / npm caches   → free: rm -rf /home/forge/.composer/cache /home/forge/.cache/composer /home/forge/.npm/_cacache"
du -sh /home/forge/.composer/cache /home/forge/.cache/composer /home/forge/.npm/_cacache /root/.composer/cache 2>/dev/null
echo "### kernels installed   → free: apt-get purge linux-image-<old>-generic linux-modules-<old>-generic"
dpkg -l 'linux-image-*' 2>/dev/null | awk '/^ii/ {print "   "$2"  "$3}'
echo "   running: $(uname -r)"
echo "### deleted-but-open files (space only returns on restart of the holder)"
lsof -nP +L1 2>/dev/null | awk 'NR>1 {s+=$7} END {printf "   %.1f MB held by %d open deleted files\n", s/1048576, NR-1}'
lsof -nP +L1 2>/dev/null | awk 'NR>1 {print "   "$1" pid "$2" "$10}' | sort | uniq -c | sort -rn | head -5
EOF
)
  run_remote_sudo "$host" "$remote_cmd"
}

# ---------------------------------------------------------------------------
# nginx-down / nginx-up
# ---------------------------------------------------------------------------
cmd_nginx_down() {
  local host=$1
  # shellcheck disable=SC2016  # the $(...) must expand on the remote, not here
  run_remote_sudo "$host" 'systemctl stop nginx; systemctl mask nginx; printf "nginx: %s / %s\n" "$(systemctl is-enabled nginx 2>&1)" "$(systemctl is-active nginx 2>&1)"'
  cat <<EOF

✓ nginx stopped and masked on $host — every site is OFFLINE and stays offline
  across do-release-upgrade's service restarts and both reboots.

Next: bin/upgrade-ubuntu.sh preflight $host
EOF
}

cmd_nginx_up() {
  local host=$1
  # shellcheck disable=SC2016  # the $(...) must expand on the remote, not here
  run_remote_sudo "$host" 'systemctl unmask nginx && nginx -t && systemctl enable --now nginx && printf "nginx: %s / %s\n" "$(systemctl is-enabled nginx)" "$(systemctl is-active nginx)"'
  cat <<EOF

✓ nginx is back on $host.

Next: bin/upgrade-ubuntu.sh verify $host
EOF
}

# ---------------------------------------------------------------------------
# prepare — sudo
# ---------------------------------------------------------------------------
cmd_prepare() {
  local host=$1
  local remote_cmd
  remote_cmd=$(cat <<EOF
set -e
B="$BACKUP_DIR"
mkdir -p "\$B"
echo "→ backups into \$B"
dpkg --get-selections | awk '\$1 ~ /^php/ && \$2 == "install" {print \$1}' > "\$B/php-packages.txt"
for b in /usr/bin/php[0-9].[0-9]; do [ -x "\$b" ] && "\$b" -m > "\$B/php-modules-\${b##*/php}.txt" 2>/dev/null || true; done
dpkg -l > "\$B/dpkg-list.txt"
[ -f "\$B/sources.list.bak" ] || cp -a /etc/apt/sources.list "\$B/sources.list.bak"
for d in sources.list.d.bak etc-php etc-nginx etc-supervisor; do rm -rf "\$B/\$d"; done
cp -a /etc/apt/sources.list.d "\$B/sources.list.d.bak"
cp -a /etc/php "\$B/etc-php" 2>/dev/null || true
cp -a /etc/nginx "\$B/etc-nginx" 2>/dev/null || true
cp -a /etc/supervisor "\$B/etc-supervisor" 2>/dev/null || true
crontab -l -u forge > "\$B/crontab-forge.txt" 2>/dev/null || true
ls /etc/nginx/sites-enabled > "\$B/sites-enabled.txt" 2>/dev/null || true
lsb_release -a > "\$B/lsb_release.txt" 2>/dev/null
echo "   \$(wc -l < "\$B/php-packages.txt") php packages recorded"
if grep -q 'mirrors.digitalocean.com' /etc/apt/sources.list; then
  echo "→ swapping apt mirror mirrors.digitalocean.com → archive.ubuntu.com"
  sed -i -E 's|https?://mirrors\.digitalocean\.com/ubuntu|http://archive.ubuntu.com/ubuntu|g' /etc/apt/sources.list
  grep -q 'mirrors.digitalocean.com' /etc/apt/sources.list && { echo "✗ a mirrors.digitalocean.com entry survived — fix /etc/apt/sources.list by hand"; exit 1; }
fi
echo "→ Prompt=lts"
sed -i 's/^Prompt=.*/Prompt=lts/' /etc/update-manager/release-upgrades
grep -q '^Prompt=lts' /etc/update-manager/release-upgrades || echo 'Prompt=lts' >> /etc/update-manager/release-upgrades
echo "→ ufw allow $FALLBACK_SSH_PORT/tcp (do-release-upgrade's fallback sshd)"
ufw allow $FALLBACK_SSH_PORT/tcp >/dev/null 2>&1 || echo "   (ufw not active or not installed — skipped)"
echo "→ apt-get update + full-upgrade (20.04 must be fully current before the release upgrade)"
apt-get update || true
DEBIAN_FRONTEND=noninteractive apt-get -y -o Dpkg::Options::=--force-confold full-upgrade
DEBIAN_FRONTEND=noninteractive apt-get -y install screen update-manager-core
apt-get -y autoremove --purge
apt-get clean
journalctl --vacuum-size=200M >/dev/null 2>&1 || true
echo "→ disk after cleanup:"
df -h / /boot 2>/dev/null | tail -n +1
[ -f /var/run/reboot-required ] && echo "→ reboot-required flag is set" || true
EOF
)
  run_remote_sudo "$host" "$remote_cmd"
  cat <<EOF

✓ $host is prepared. Backups are in $BACKUP_DIR on the box.

NOW, BY HAND:
  1. Reboot:    ssh $host sudo reboot        (or Forge dashboard → Reboot Server)
  2. Wait for it to come back, then run the upgrade inside screen:
                ssh -t $host sudo screen -S upgrade do-release-upgrade
     Answers:   third-party sources disabled → yes
                "Start the upgrade? (y/N/d)" → d, read the removal list,
                   N if any php* or mysql-community-* package is listed
                modified config files → keep yours (N)
                remove obsolete packages → No
                restart services automatically → yes
     Dropped?   ssh -t $host sudo screen -x
  3. Reboot again when it says so, then:
                bin/upgrade-ubuntu.sh --drop-php=... --disable=... postflight $host
EOF
}

# ---------------------------------------------------------------------------
# postflight — sudo
# ---------------------------------------------------------------------------
cmd_postflight() {
  local host=$1
  local remote_cmd
  remote_cmd=$(cat <<EOF
set -e
B="$BACKUP_DIR"
TARGET="$TARGET_CODENAME"
DROP="$DROP_PHP"
DISABLE="$DISABLE_SITES"
code=\$(lsb_release -cs)
[ "\$code" = "\$TARGET" ] || { echo "✗ box is on \$code, expected \$TARGET — do-release-upgrade has not completed"; exit 1; }
[ -f "\$B/php-packages.txt" ] || { echo "✗ \$B/php-packages.txt missing — was prepare run?"; exit 1; }
echo "→ ondrej/php for \$code"
rm -f /etc/apt/sources.list.d/ondrej-ubuntu-php-*.list.distUpgrade
add-apt-repository -y ppa:ondrej/php >/dev/null
apt-get update || true
echo "→ PHP package list (dropping: \${DROP:-nothing})"
want=\$(cat "\$B/php-packages.txt")
for v in \$(echo "\$DROP" | tr ',' ' '); do want=\$(echo "\$want" | grep -v "^php\$v" || true); done
install=""
for p in \$want; do
  if apt-cache show "\$p" >/dev/null 2>&1; then install="\$install \$p"; else echo "   skip \$p (not available on \$code)"; fi
done
echo "→ installing \$(echo \$install | wc -w) PHP packages"
DEBIAN_FRONTEND=noninteractive apt-get -y -o Dpkg::Options::=--force-confold install \$install
DEBIAN_FRONTEND=noninteractive apt-get -y -o Dpkg::Options::=--force-confold full-upgrade
for v in \$(echo "\$DROP" | tr ',' ' '); do
  if dpkg -l "php\$v*" 2>/dev/null | grep -q '^ii'; then
    echo "→ purging php\$v packages"
    DEBIAN_FRONTEND=noninteractive apt-get -y purge "php\$v*" || true
  fi
done

    esac
  done < <(site_list "$host")
```

## Analysis

This is a new capability. Today `docs/faq/ubuntu20.md` option B is a manual runbook, and
`php-patcher.sh` only diagnoses and patches PHP. The new script is a **separate bashew script**
next to it. It does everything around `do-release-upgrade` over SSH, with one verb per stage, and
each verb prints the next step.

**How it is meant to be used:** an admin runs it with help from Claude Code. The admin types the
sudo password once (`password` verb, needs a terminal). It is stored encrypted, and from then on
the non-interactive verbs can be run by the admin *or* by Claude through its Bash tool. The steps
that need a human at a terminal are `password`, the `do-release-upgrade` run inside `screen`, the
reboots, and `dpkg-reconfigure mysql-apt-config`. The script prints the exact command for each of
them. The admin pastes the output back to Claude. Every verb also saves its output to a local log
file and ends with machine-readable `STATUS:` and `NEXT:` lines, so Claude can read the result
without copy/paste.

**Taken from the reference script:** one verb per stage, a read-only preflight with a
READY/BLOCKED verdict, nginx masked for the whole upgrade, backups in `/var/backups/ubuntu-upgrade`,
the DO mirror swap, port 1022, `Prompt=lts`, reinstalling the saved PHP package list, restarting
php-fpm and the supervisor workers, HTTPS probes, cleanup. The script never runs `sudo reboot` by
itself.

**Added from the 2026-10-22 runbook:** comment out the duplicate source line after the mirror swap;
detect Oracle MySQL and warn about 8.4/9.x; flag dead third-party sources (`node_1x.x`,
`ppa.setup-php.com`, the ondrej nginx/apache2 PPAs on focal); a full DB dump, stored on the box
*and* streamed to the workstation; mention the composer cache in the disk advice; two hops to
noble (deb822 `.sources` files on noble).

**Dropped from the reference:** the `bin/forge_mgt.sh`, `bin/fix_copyfail.sh` and
`bin/fingerprint.sh` calls, the `docs/concepts`/`docs/sources` paths, the incident-specific
"leftover mitigation" greps (memory_limit=-1, multipart, algif), and `<HOST>_SUDO_PASSWORD` in
`.env`, which the encrypted password store replaces.

**Risks:** the script runs root commands on production servers. Every sudo verb must be idempotent
(safe to re-run after a dropped connection), must refuse to run on the wrong codename, and must
never delete anything outside the backup folder and known upgrade leftovers. The sudo password must
never appear on a command line, in a log, or in Claude's context.

## PRP

### Goal

A new `upgrade-ubuntu.sh` at the repo root (bashew 1.22.1, same layout as `php-patcher.sh`).
It drives an in-place Ubuntu LTS upgrade of a Laravel Forge / DigitalOcean server over SSH, from
20.04 through 22.04 to 24.04, one verb per stage. It is safe to run either by an admin or by
Claude Code acting for that admin. The interactive parts (sudo password entry, `do-release-upgrade`,
reboots, `dpkg-reconfigure mysql-apt-config`) stay with the human, and the script prints their
exact commands.

### Why

- On a focal server, `php-patcher --patch` cannot fix PHP anymore: no repository builds PHP 8.x for
  20.04 (ubuntu20.md). The only fix is an OS upgrade, which is long, risky and full of known traps
  (DO mirror, the obsolete-packages prompt removing PHP, Oracle MySQL, dead sources, a full disk).
- The manual runbook worked, but every step was typed by hand and checked by eye. A scripted,
  verb-per-stage flow with READY/BLOCKED verdicts, local logs and STATUS/NEXT lines lets Claude
  check each stage and tell the admin exactly what to do next.
- It ends where php-patcher starts again: after `postflight`, `php-patcher host <host>` reports
  OK/PATCH, and `php-patcher --patch` works.

### Decisions taken

- Script framework → separate bashew script built like `php-patcher.sh`; no new verbs in php-patcher (user).
- Password storage → asked once by `password <host>` (TTY), then `openssl enc -aes-256-cbc -pbkdf2`
  file per host in `~/.config/upgrade-ubuntu/<host>.pw.enc`; one random 256-bit key in the macOS Keychain
  (service `upgrade-ubuntu`, account `key`), on Linux in `~/.config/upgrade-ubuntu/.key` (0600);
  a `forget` verb; `cleanup` on the final target forgets it (user picked the recommendation).
- Default target → `noble`, two hops; the hop is worked out from the box's codename (focal→jammy,
  jammy→noble); `--target=jammy` stops after one hop (user).
- Reboots → always manual; the script prints `ssh -t <host> sudo reboot` (or the Forge dashboard)
  and never reboots by itself (user).
- nginx → mandatory: preflight is BLOCKED unless nginx is stopped and masked; it stays masked
  across both hops and comes back only with `nginx-up` after verify passes on the final target (user).
- Who runs the sudo verbs → either one: with a stored password they need no TTY and Claude may run
  them; `-f` skips `IO:confirm`, and Claude's own Bash permission prompt is the confirmation (user).
- Output for Claude → every verb tees its output to `$LOG_DIR/<host>/<ts>.<verb>.log` and ends with
  `STATUS: <WORD> <detail>` and `NEXT: <command>`; a read-only `status` verb works out the stage
  from the box; a `logs` verb shows the dist-upgrade and screen logs from the box (user).
- DB dump → in `prepare`: `mysqldump --all-databases --single-transaction --routines --events`,
  gzip, streamed once with `tee` into `/var/backups/ubuntu-upgrade/<hop>/all-databases.sql.gz` (0600)
  *and* to `$LOG_DIR/<host>/all-databases.<ts>.sql.gz` (0600) on the workstation; `--no-dump` skips it (user).
- `do-release-upgrade` → never non-interactive. An `upgrade` verb runs
  `ssh -t <host> sudo screen -L -Logfile /var/log/dist-upgrade/screen.log -S upgrade do-release-upgrade`
  only when there is a TTY and never with `-f` alone; otherwise it prints that command with
  STATUS NEEDS-ADMIN (default, following the user's "admin runs interactive steps").
- `mysql-apt-config` → not automated: postflight prints `ssh -t <host> sudo dpkg-reconfigure mysql-apt-config`
  with STATUS NEEDS-ADMIN when Oracle MySQL is installed (default: the dialog picks the release + series,
  and the repo key situation in apt.md varies).
- Oracle MySQL 8.4/9.x → a warning, not a blocker: they stay on repo.mysql.com; the danger is only
  swapping to Ubuntu's 8.0 (ubuntu20.md) (default; corrects the earlier "BLOCK" idea).
- Between hops, sites stay down (nginx masked); postflight on jammy reinstalls PHP and then points to
  prepare for the noble hop; `verify --target=jammy` remains possible for an intermediate check (default).
- Site list for verify → `/etc/nginx/sites-enabled` file names minus `default`/`000-*`; no Forge API (default).
- Fixed versions → option `fixed` with php-patcher's default `8.5.12 8.4.27 8.3.36 8.2.35`
  (space-separated, same format) (default).
- The reference's `.env` `<HOST>_SUDO_PASSWORD` → dropped (replaced by the encrypted store) (default).

| prepare | sudo | no* | backups, dump, mirror swap, dedupe, Prompt=lts, ufw 1022, full-upgrade, screen+update-manager-core |
| upgrade | admin, interactive | yes | `ssh -t … sudo screen -L … do-release-upgrade`, else prints it |
| logs | sudo | no* | tail of /var/log/dist-upgrade/{main,apt,term,screen}.log, errors grepped |
| postflight | sudo | no* | re-add ppa:ondrej/php, reinstall PHP, full-upgrade, restart fpm+supervisor, list disabled sources |
| verify | ssh user + sudo | no* | OS/kernel/PHP vs --fixed/fpm/mysql/nginx/stale binaries + HTTPS probes from here |
| cleanup | sudo | no* | ufw delete 1022, remove *.distUpgrade/*.save, autoremove; on final target also `forget` |

\* no TTY needed when a password is stored; without one: `STATUS: NEEDS-ADMIN` + `NEXT: ./upgrade-ubuntu.sh password <host>`.

### Known gotchas & library quirks

- CRITICAL stdin: never feed a remote script to `bash -s` *and* run apt/dpkg in it; they can eat
  the rest of the script. Use the reference's pattern: password as the only stdin line, script as
  an argument: `printf '%s\n' "$pw" | ssh -T -o BatchMode=yes -o ConnectTimeout=10 "$host" "sudo -k -S -p '' env LC_ALL=C.UTF-8 DEBIAN_FRONTEND=noninteractive bash -c $(printf '%q' "$cmd")"`.
  After sudo reads the password, stdin is at EOF, so any dpkg prompt gets EOF instead of hanging.
  Also pass `-o Dpkg::Options::=--force-confold`.
- CRITICAL password hygiene: decrypt into a local variable only (`pw=$(K=$key openssl enc -d … -pass env:K -in "$f")`),
  never `export` it, never `IO:debug` it, `unset pw` after use. `set -x`/`-V` must not reveal it: do not
  pass it through any function argument that IO:debug prints.
- ssh joins its arguments with spaces: anything passed to the remote side (fixed versions, site lists)
  must go through `printf %q` or into the quoted `bash -c` script.
- OpenSSH 10 prints `** WARNING: connection is not using a post-quantum key exchange` on stderr:
  filter `^\*\* ` the way php-patcher does before showing stderr.
- bashew: `IO:confirm` returns false when it cannot read (no TTY) unless `FORCE=1`. Mutating verbs:
  `IO:confirm "… on $host?" || IO:die "cancelled (use -f when running without a terminal)"`.
- bashew `$LOG_DIR` defaults to `$HOME/log/$script_prefix` = `~/log/upgrade-ubuntu`; make
  `$LOG_DIR/<host>` with `chmod 700`. Tee the verb's stdout+stderr there (`exec > >(tee -a "$log") 2>&1`
  inside the verb function, or wrap the call in Script:main), filtering nothing secret because nothing secret is printed.
- Both scripts sit in the same folder, so they share `VERSION.md` and the `.env` files bashew loads. That is fine and intended.
- Hop logic: `next_codename focal` → jammy, `jammy` → noble, anything else → empty (stop). prepare refuses
  when the box's codename is already the target, or is not focal/jammy. postflight reads the hop from
  `/var/backups/ubuntu-upgrade/<from>-to-<to>/` and refuses unless `lsb_release -cs` == `<to>`.
- Backups are per hop: `/var/backups/ubuntu-upgrade/focal-to-jammy/…` and `…/jammy-to-noble/…`,
  so the second prepare does not overwrite the first hop's `sources.list.bak`.
- noble uses deb822: the Ubuntu archive moves to `/etc/apt/sources.list.d/ubuntu.sources`, and
  `add-apt-repository` writes `ondrej-ubuntu-php-noble.sources`. Disabled-source detection must grep
  `*.list` *and* `*.sources` (in .sources the upgrader writes `Enabled: no`).
  On jammy the mirror swap is in `sources.list`; on noble check `ubuntu.sources` too for `mirrors.digitalocean.com`.
- The duplicate-line fix after the mirror swap: comment out *exact* duplicate `deb` lines only,
  `awk '/^deb /{ if (seen[$0]++) { print "# duplicate (upgrade-ubuntu): " $0; next } } { print }'`,
  written to a temp file and moved into place.
- Dead source patterns for preflight (warn, prepare does not touch them; the upgrader disables them):
  `deb.nodesource.com/node_1[0-6]\.x`, `ppa.setup-php.com`, `ppa.launchpad(content)?.net/ondrej/(nginx|apache2)` on focal.
- MySQL dump auth: try `mysqldump` as root over the socket first (`sudo` → auth_socket or `/root/.my.cnf`).
  If that fails with "Access denied", stop with `STATUS: BLOCKED dump: root cannot log in to MySQL` and
  `NEXT:` to create `/root/.my.cnf` (`[client] user=root password=…`, chmod 600; the password is in the
  Forge server's provisioning email) or to re-run with `--no-dump`. Check free space against `du -sh /var/lib/mysql` first.
- Streaming the dump: in a separate ssh call, stdout carries the gzip stream and stderr carries messages:
  `… bash -c 'set -o pipefail; mysqldump … | gzip | tee "$B/all-databases.sql.gz"; chmod 600 "$B/all-databases.sql.gz"'` > local file.
  Check the local file with `gzip -t` and a size > 0 afterwards.
- `apt-get update` may fail on the expired MySQL key or a dead source: run `apt-get update || true`, then
  check that the Ubuntu archive lines were fetched (`apt-cache policy | grep -q "archive.ubuntu.com.*${codename}"`).
- `do-release-upgrade` without `Prompt=lts`, or on a non-updated system, prints `No new release found`;
  prepare fixes both. Port 1022: `ufw allow 1022/tcp`, and `|| true` when ufw is inactive.
- Keychain: on macOS `security add-generic-password -U -s upgrade-ubuntu -a key -w "$key"` and
  `security find-generic-password -s upgrade-ubuntu -a key -w`. Detect it with `[[ $(uname) == Darwin ]] && command -v security`.
  An env var `UPGRADE_UBUNTU_KEYSTORE=file|keychain` overrides the detection (the tests use it).
- `status` must work out the stage without sudo: codename, `systemctl is-enabled nginx`, the presence of
  `/var/backups/ubuntu-upgrade/<hop>` (world-readable dir; make prepare `chmod 755` the dir and `600` the files),
  `/var/run/reboot-required`, `screen -ls` as root is not visible → use `pgrep -f do-release-upgrade`,
  and `/var/log/dist-upgrade/main.log` mtime.
- Public repo: no real server names in examples, tests or docs (use `myhost`, `web1`, `focal1`, …).

### Anti-patterns

- Don't invent new patterns when existing ones work: copy php-patcher's bashew frame, IO:* functions and ssh options.
- Don't put the sudo password in argv, env, logs, IO:debug, or a temp file in plaintext, not even briefly.
- Don't run `do-release-upgrade` non-interactively, and don't reboot from the script.
- Don't `bash -s` a script that runs apt/dpkg (stdin theft); use `bash -c "$(printf %q …)"`.
- Don't delete anything outside `/var/backups/ubuntu-upgrade`, `*.distUpgrade`, `*.save` and apt caches.
- Don't skip validation because "it should work"; don't mock to make a test pass.
- Don't use real host names anywhere (public repo).

**9/10** that an agent can build this in one pass from this file and the repo. What could still go

Level 3 checks and by the BLOCKED/NEEDS-ADMIN fallbacks, not by guessing.
