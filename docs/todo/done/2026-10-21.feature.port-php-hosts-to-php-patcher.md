# Port php_hosts.sh functionality into php-patcher.sh verbs

## Request
copy the functionality of @docs/inspiration/php_hosts.sh into the bashew script @php-patcher.sh
php-patcher host <host>
php-patcher file <file with list of hosts>
php-patcher auto (all hosts from $HOME/.ssh/config)
php-patcher --patch auto (don't just show, also patch)

Added 2026-10-21 (during planning):
also add php-patcher --pick auto/file <file>: it shows the list and lets the user pick 1 to run the script on (using fzf if possible)
can we also allow php-patcher host <host1> <host2> <host3> ?

## Analysis
This is a feature: `php-patcher.sh` is a fresh bashew 1.22.1 skeleton with only the placeholder
verbs `action1`/`action2`. All the logic exists in `docs/inspiration/php_hosts.sh`, a plain
bash script with hand-rolled argument parsing. The job is to rebuild it inside bashew's
conventions: `Option:config()` holds the flags/options/verbs, `Script:main()` dispatches, and
`do_*` helpers do the work.

How the old options map to bashew:

| php_hosts.sh | php-patcher.sh |
|---|---|
| `web1 web2` (positional) | `host <h1>[,<h2>,…]` verb (comma-separated list in 1 arg, `param|?|input`) |
| `-f hosts.txt` | `file <hostfile>` verb (same parsing: one per line, `#` comments, first word only) |
| `--all` | `auto` verb (Hosts from `~/.ssh/config` + Includes, minus wildcards/negations, git hosts, duplicates by HostName:Port via `ssh -G`) |
| `--upgrade` | `flag|p|patch` → `$patch` |
| `--yes` | built-in `-f/--FORCE` (`IO:confirm` already skips the prompt when FORCE is set) |
| `-x REGEX` | `option|x|exclude` |
| `--list` | `flag|l|list` |
| (new) | `flag|i|pick`: pick 1 host from the `file`/`auto` list interactively (bashew `Tool:pick`: fzf → gum → numbered menu) |
| `PHP_FIXED` env | `option|F|fixed|...|8.5.12 8.4.27 8.3.36 8.2.35`. bashew's `.env` loading still lets users override it |

Risks are listed under PRP → Known gotchas.

## Acceptance criteria
- `php-patcher host <host>` prints the OS and PHP CLI/FPM versions with OK/PATCH/EOL status for that host
- `php-patcher host web1,web2,web3` does the same for each listed host, in order (empty items and duplicates ignored)
- `php-patcher file hosts.txt` does the same for every host in the file (blank lines and `#` comments ignored)
- `php-patcher auto` uses every usable Host from `~/.ssh/config` and its Include files, skipping
  wildcards, negations, git hosts, `-x` matches and HostName:Port duplicates
- `php-patcher -l <verb> …` prints the selected hosts, one per line, and exits 0 without connecting to anything
- `php-patcher --pick auto` / `php-patcher --pick file hosts.txt` shows the host list (fzf if installed,
  else gum, else a numbered menu) and runs on the 1 picked host only; combinable with `--patch`;
  cancelling the pick exits without connecting; `--pick host a,b,c` picks from that list (a single host runs without a picker);
  `--pick` with `-l`, or without a terminal, is refused with a clear message
- `php-patcher --patch <verb>` upgrades the PHP packages, restarts FPM, reloads Apache with mod_php, and shows the versions again;
  it **always** asks for confirmation first (host, file and auto) unless `-f` is given
- Fixed versions can be set with `--fixed` or `.env` (`fixed=...`), and are validated
- A failed host (ssh error or upgrade error) shows `FAILED` and doesn't stop the remaining hosts; the script then exits **1**
- `bash -n`, `shellcheck` and `bats tests/` pass; `-h` shows the new verbs and TIPs; the placeholder verbs are gone

## PRP

### Goal
`php-patcher.sh` is a working bashew CLI with three host sources (`host <name>[,<name>…]`,
`file <path>`, `auto`) and the flags `-p/--patch`, `-l/--list`, `-i/--pick`, `-x/--exclude <regex>` and
`-F/--fixed "<versions>"`. Without `--patch` it is read-only and prints, per host, the OS and every
PHP binary (cli + each php-fpm) with an OK / PATCH (fixed in x.y.z) / EOL status. With `--patch`
it upgrades the installed PHP packages (apt or dnf/yum), restarts the running php-fpm services,
reloads Apache when mod_php is enabled, and shows the versions again. It behaves the same as
`docs/inspiration/php_hosts.sh`, wrapped in bashew conventions, and comes with offline bats tests.

### Why
- One command to audit, and optionally patch, PHP on every server in `~/.ssh/config` after a PHP security release
- bashew adds `-h` with TIPs, `.env` config, logging, `install` (symlink + completion) and `update`
- The old script stays in `docs/inspiration/` as reference only; this one replaces it

### Decisions taken
- Dry run (old `--list`) → `-l/--list` flag that works with every source, prints the hosts and exits 0 (user)
- Confirmation before patching → **always** for host, file and auto, skipped with `-f/--FORCE` (user)
- Exit code when hosts fail → exit 1 after cleanup, despite bashew's `Script:exit` always exiting 0 (user)
- Tests → offline bats tests in `tests/`, with a fake `ssh` on PATH; no real SSH needed (user)
- Several hosts for `host` → comma-separated in one argument: `host web1,web2,web3` (user). Space-separated `host h1 h2 h3` was rejected: bashew's `param|n` is always required (≥1), which would break `auto` without arguments, and the only fix is editing bashew core below DO NOT MODIFY
- Old `--yes` → bashew's `-f/--FORCE`; old `-f hostfile` → `file` verb, because `-f` is taken (default)
- `PHP_FIXED` → option `fixed` (`-F`), default `8.5.12 8.4.27 8.3.36 8.2.35`; settable as `fixed="…"` in `.env` (default)
- README.md is created with usage, examples and the "check PHP_FIXED against php.net" warning (default)
- `--pick` added on user request → flag `-i/--pick` (`-p` is taken by `--patch`), uses bashew's built-in `Tool:pick` (fzf → gum → numbered menu), no new picker code (Claude)
- `--pick` with `-f`: `Tool:pick` would silently return the FIRST host when FORCE=1 → call it as `FORCE=0 Tool:pick …` so the user always picks; `-f` still skips the patch confirmation afterwards (Claude)
- `--pick` without a terminal (cron/CI) → `IO:die`, never a silent default pick (Claude)
- `--pick` with `host` → allowed (picks from the comma list; with 1 host, no picker). `--pick` with `-l` (contradictory) → `IO:die` (Claude)

### Known gotchas & library quirks
- **CRITICAL IFS**: bashew sets `IFS=$'\n\t'` (l.208), so unquoted `$var` no longer splits on spaces.
  Wherever space splitting is needed (Include file lists, `$fixed` validation loop), use
  `local IFS=' '` inside the function or `read -ra arr <<<"$var"`. The ssh remote command is
  one string (`"bash -s -- $patch $fixed"`), so it's fine as is.
- **Glob expansion of Include**: the old code relies on unquoted `for f in $inc` for globs. Under
  bashew's IFS that still globs (IFS doesn't affect globbing), but with no match the pattern stays
  literal, which the `[[ -r $f ]]` check in the function already handles.
- **Exit code**: `Script:exit` always does `exit 0`, and the EXIT trap calls `IO:die` on any
  plain `exit`. For exit 1: `trap - INT TERM EXIT` first, log, then `exit 1`. No temp files are
  used, so skipping `Script:exit`'s cleanup loses nothing; still call `IO:debug` for symmetry.
- **Flag order**: `php-patcher auto --patch` does NOT work (`--patch` lands in `$input`, and with
  `auto` that must be rejected). Validate: for `auto` `$input` must be empty, otherwise
  `IO:die "auto takes no argument; put flags before the verb: $script_prefix --patch auto"`.
- **Choice substring grep** (l.1081): `ho` would pass as a valid choice and then hit the `*)`
  case → `IO:die "action [...] not recognized"`. That's fine, leave bashew as is.
- **Command injection**: `$fixed` is interpolated into the remote command line. Validate each word
  against `^[0-9]+\.[0-9]+\.[0-9]+$`, else `IO:die`. Host names (from argument, file or config)
  must not start with `-` (ssh option injection): reject them in `host`, and skip them with
  `IO:alert` in `file`.
- **stdin in loops**: in the `auto` collector, `ssh -n -G` must keep `-n` (the loop reads from a
  process substitution). The run loop feeds the remote script with `<<<"$remote"`, which is fine.
- `IO:confirm` uses `read -n 1` from stdin; call it once, before the host loop.
- `-Q` (QUIET) silences `IO:print`. Print the `== host` header via `IO:print`; the remote ssh output is passed through unchanged.
- `Os:require "ssh"` and `Os:require "awk"` go in `Script:main` (the existing `Os:require "awk"` is already there).
- Tests must not touch the real `~/.ssh` or real servers: override `HOME` with a temp dir and put
  `tests/fixtures/bin` first on `PATH`. The script's default `LOG_DIR=$HOME/log/...` then lands in the temp HOME (good).
- `ssh -G` with an alias that has no HostName prints `hostname <alias>`, so aliases without a HostName never collide.
- Options short letters in use: h Q V f L T. New: p l i x F (case-sensitive, `-F` ≠ `-f`).
- **Tool:pick** (php-patcher.sh l.407-487, below DO NOT MODIFY, use as-is): options on stdin, choice on
  stdout, returns 1 when cancelled/empty. It returns the default (first option) WITHOUT asking when
  `FORCE=1` or when `Os:has_tty` is false → so check `Os:has_tty` yourself first and call it with a
  temporary `FORCE=0` (bash prefix assignment works on functions: `choice=$(FORCE=0 Tool:pick "Pick a host:" < <(printf '%s\n' "${hosts[@]}"))`).
  Don't pass the `other` argument (no free-text host).
- Tests: bats run from a terminal still has `/dev/tty`, so a real fzf would hang. Put a fake `fzf`
  in `tests/fixtures/bin` (prints the 2nd stdin line). Guard the pick test with
  `( : </dev/tty ) 2>/dev/null || skip "no tty"` because in CI `Os:has_tty` is false.

- Don't change docs/inspiration/php_hosts.sh
- Don't hardcode the fixed versions anywhere other than the `fixed` option default
