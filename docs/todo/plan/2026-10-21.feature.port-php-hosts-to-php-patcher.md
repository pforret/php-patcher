# Port php_hosts.sh functionality into php-patcher.sh verbs

## Request
copy the functionality of @docs/inspiration/php_hosts.sh into the bashew script @php-patcher.sh
php-patcher host <host>
php-patcher file <file with list of hosts>
php-patcher auto (all hosts from $HOME/.ssh/config)
php-patcher --patch auto (don't just show, also patch)

## Analysis
This is a feature: `php-patcher.sh` is a fresh bashew 1.22.1 skeleton with only the placeholder
verbs `action1`/`action2`. All the logic exists in `docs/inspiration/php_hosts.sh`, a plain
bash script with hand-rolled argument parsing. The job is to rebuild it inside bashew's
conventions: `Option:config()` holds the flags/options/verbs, `Script:main()` dispatches, and
`do_*` helpers do the work.

How the old options map to bashew:

| php_hosts.sh | php-patcher.sh |
|---|---|
| `web1 web2` (positional) | `host <host>` verb + `param|?|input` |
| `-f hosts.txt` | `file <hostfile>` verb (same parsing: one per line, `#` comments, first word only) |
| `--all` | `auto` verb (Hosts from `~/.ssh/config` + Includes, minus wildcards/negations, git hosts, duplicates by HostName:Port via `ssh -G`) |
| `--upgrade` | `flag|p|patch` → `$patch` |
| `--yes` | built-in `-f/--FORCE` (`IO:confirm` already skips the prompt when FORCE is set) |
| `-x REGEX` | `option|x|exclude|skip hosts matching this regex` |
| `--list` | open: a `list` verb, or a `--list` flag |
| `PHP_FIXED` env | `option|F|fixed|...|8.5.12 8.4.27 8.3.36 8.2.35`. bashew's `.env` loading still lets users override it |

The remote heredoc script (`status`, `show`, `do_upgrade`) can be copied as-is. It runs in the
remote bash, so bashew's local settings don't touch it.

Risks and pitfalls:
- **bashew sets `IFS=$'\n\t'`**, so unquoted expansions no longer split on spaces. In
  `ssh_config_hosts` the line `for inc in ${line#INCLUDE }` breaks when an Include lists several
  files. The `$fixed` list and `$PHP_FIXED` also rely on space splitting. Fix: use a local
  `IFS=' '` or `read -ra`.
- **The `Script:exit` trap always exits 0.** The old script returned `rc=1` when any host failed.
  Keep that by calling `exit 1` explicitly after cleanup, or decide that a non-zero exit isn't
  needed.
- **bashew's choice validation** uses `grep "$1"` against the choice list, which is a substring
  match. `host`, `file` and `auto` don't collide with anything, but keep verb names distinct.
- **`ssh` inside loops that read from stdin**: the `auto` collection loop must keep `ssh -n -G`.
- **Confirmation**: the old script only asked before `--all --upgrade`. Decide whether
  `--patch` should also ask for `host`/`file` (my recommendation: always ask before patching
  unless `-f`).
- The `PHP_FIXED` defaults are *expected* 21 Oct 2026 releases. Keep the warning in the help/TIPs.
- Built-in `-f` means `--FORCE`, so the old `-f hostfile` short option can't be reused. That's
  why `file` is a verb.

## Impacted files
- `php-patcher.sh` — config lines, `Script:main` cases with TIPs, `do_host`/`do_file`/`do_auto`
  helpers, `ssh_config_hosts`, the remote script, the per-host run loop; remove `action1`/`action2`
- `README.md` — new: usage and examples (optional, the repo has none yet)

## Plan
1. `Option:config()`: add `flag|p|patch`, `option|x|exclude`, `option|F|fixed` (with default),
   and change the choice line to `host,file,auto,check,env,install,update` (+ `list` if chosen);
   reword `param|?|input` to "host name or host file".
2. Port `ssh_config_hosts` as `Ssh:config_hosts` (or a `do_` helper), splitting Include lists
   correctly despite bashew's IFS.
3. Write the host collectors: `hosts_from_arg` (host), `hosts_from_file` (file),
   `hosts_from_ssh_config` (auto: skip wildcards, `!`, git hosts, `$exclude`, HostName:Port duplicates).
4. Put the remote script in a function that prints the heredoc (`remote_script`).
5. `run_hosts`: if `$patch` is set, `IO:confirm` listing the hosts; then for each host print `== host`,
   run `ssh -o BatchMode=yes -o ConnectTimeout=10 "$h" "bash -s -- $patch $fixed"`, track failures
   and report a summary (IO:success / IO:alert).
6. Wire up `Script:main` cases `host`, `file`, `auto` with `#TIP:` lines; require `ssh` and `awk` via `Os:require`.
7. Remove the `action1`/`action2`/`action3` placeholders.
8. Test: `bash -n`, `shellcheck php-patcher.sh`, `./php-patcher.sh -h`,
   `./php-patcher.sh check`, `auto` against the real `~/.ssh/config` (show only), `host`
   against one reachable server.

## Acceptance criteria
- `php-patcher host <host>` prints the OS and PHP CLI/FPM versions with OK/PATCH/EOL status for that host
- `php-patcher file hosts.txt` does the same for every host in the file (blank lines and `#` comments ignored)
- `php-patcher auto` uses every usable Host from `~/.ssh/config` and its Include files, skipping
  wildcards, negations, git hosts, `-x` matches and HostName:Port duplicates
- `php-patcher --patch <verb>` upgrades the PHP packages, restarts FPM, reloads Apache with mod_php, and shows the versions again;
  it asks for confirmation first unless `-f` is given
- Fixed versions can be set with `--fixed` or `.env` (`fixed=...`)
- A failed host (ssh error or upgrade error) shows `FAILED` and doesn't stop the remaining hosts
- `bash -n` and `shellcheck` pass; `-h` shows the new verbs and TIPs; placeholder verbs are gone
